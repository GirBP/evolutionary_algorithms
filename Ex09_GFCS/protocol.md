## 0. Преамбула

### 0.1 Мета методології
Ітеративний метод дослідження: кожна ітерація (exploration) звужує простір гіпотез через перевірку на новизну (Novelty Check), доведення структурних обмежень (Impossibility Proofs) та прогресивне масштабування набору даних (Tier 1→4).

### 0.2 Структура протоколу
Кожна ітерація (exploration) має тип, гіпотезу, код, результат і тригер переходу до наступної.
Стан дослідження фіксується у файлі `plan.md` після кожної ітерації.

### 0.3 Анти-bias правила
- **Steelman**: перед спростуванням — сформулювати найсильніший аргумент ЗА
- **Source > Prior**: результат виконання коду має пріоритет над літературними priors
- **[SURPRISING]**: обов'язковий тег для контрінтуїтивних результатів
- **Stop condition**: зупиняти гілку, якщо 2 ітерації поспіль дають неробочий код або повторюють відкинуті ідеї
- **No-tuning rule**: коли Scaling ламається — ЗАБОРОНЕНО підбирати гіперпараметри. Одразу вимагати доказ бар'єру.

### 0.4 Перевірка на плагіат (Novelty Check)

База: 18 математичних операторів з 15 робіт (файл `ex09_math_apparatus.md`).

**Контрольні точки:**

1. **Після Formalization (п. 2)**: перевірити чи постановка задачі не ідентична існуючій.
2. **Після кожної Hypothesis (п. 3, і далі)**: перед кодом — описати оператор словами і перевірити чи він зводиться до одного з 18 операторів через підстановку змінних.
3. **Після Synthesis (п. 8)**: фінальна поопераційна перевірка кожного компонента фінального алгоритму проти всіх 18 операторів.

**Критерій ідентичності**: якщо наш оператор Ψ зводиться до оператора Ψ' з бази через перейменування змінних — це плагіат. Якщо є хоча б один структурний елемент що не зводиться — фіксуємо різницю у NOVELTY CLAIM.

**Категорії операторів для перевірки:**
- A: Activation-based similarity (WANDA, top-p, ZipIt)
- B: Neuron clustering (Kim NeurIPS'20, K-means, Optimal, Functional)
- C: Per-layer optimization (AMC RL, Sheared LLaMA Lagrange)
- D: Weight compensation (SparseGPT H⁻¹, OBC)
- E: Structured→dense (Network Slimming, BUnit-Net)
- F: Knowledge Distillation (Hinton, Caruana)
- G: SVD (Denton, Fisher-weighted)
- H: Optimal Transport (Singh Wasserstein)

### 0.5 Прогресивне додавання датасетів

**Порядок:**
1. **Tier 1 (Hypothesis + Novelty Check)**: moons, circles — 2 базових, швидкі
2. **Tier 2 (Scaling — прості)**: spirals, blobs — після проходження Novelty Check
3. **Tier 3 (Scaling — складні)**: gaussian_quantiles, classification — різні класи
4. **Tier 4 (Scaling — різна зв'язність)**: highdim (50D), sequence_cls (16D) — різна структура

**Правило**: датасети Tier N+1 додаються ТІЛЬКИ після успішного тестування на Tier N.
Якщо метод ламається на новому Tier — повертатись до Reframing, НЕ підлаштовувати гіперпараметри.

### 0.6 Контроль якості ітерацій
Кожна ітерація фіксується разом з гіпотезою, кодом і результатом виконання; хибні гілки зупиняються за критерієм Stop condition (§0.3), а не підбором параметрів заднім числом.

### 0.7 Фільтрація контексту
- У `plan.md` передавати тільки **Actionable Conclusions** та математичні інсайти
- Сирий код невдалих експериментів відсіювати

### 0.8 Мета-протокол
- **Прогрес** вимірюється **звуженням простору пошуку**, а не зростанням accuracy на 0.1%
- Наявність тегів **[SURPRISING]** вказує що пайплайн долає локальні мінімуми
- `plan.md` автоматично стає структурою дисертації:
  - Impossibility Proofs → Огляд та постановка задачі
  - Reframing → Методологія
  - Revision + Synthesis + Scaling → Експериментальна частина

## 2. Формалізація задачі  ВИКОНАНО

### 2.1 Математична постановка

**Дано:**
- f_S: sparse мережа з параметрами θ ⊙ M, де θ ∈ ℝ^N, M ∈ {0,1}^N
- Q(f_S): якість (F1-weighted) на тестовому наборі
- T(f_S): час інференсу на цільовому залізі

**Знайти** сюр'єкції π_l: [n_l] → [k_l] для кожного прихованого шару l та оператор синтезу ваг Ψ, що:

$$\min_{\pi, k} \sum_{l=1}^{L+1} k_l \cdot k_{l-1}$$

$$\text{s.t.} \quad \| f_S - f_C(\Psi(\theta \odot M, \pi)) \|_{L^2(\mathcal{D})} \leq \varepsilon$$

де k₀ = d, k_(L+1) = C — фіксовані.

### 2.2 Метрика успіху
- **Первинна**: реальний speedup S = T(f_S) / T(f_C) при Q(f_C) ≥ Q(f_S) - ε
- **Вторинна**: compression ratio R = N / N', де N' = Σ k_l · k_(l-1)

## 3. Exploration 1 — Hypothesis + Code

### 3.1 Тип
Hypothesis + Code (верифікація на Tier 1: moons, circles)

### 3.2 Гіпотеза
Запропонований метод конверсії дає реальний speedup при збереженні якості.

### 3.3 Порядок дій
1. Описати оператор Ψ словами
2. **Novelty Check** проти категорій A–H
3. Якщо CONFLICT → змінити оператор до проходження
4. Якщо OK → реалізувати код
5. Запустити на Tier 1 (moons, circles) × 2 seeds
6. Заміряти: speedup, F1, compression ratio

### 3.4 Критерій успіху
- speedup > 1.0
- Q(f_C) ≥ Q(f_S) − 0.02
- Novelty Check: OK по всіх 8 категоріях

### 3.5 Тригер переходу
- Якщо успіх + novelty OK → **Exploration 2 (Scaling Tier 2)**
- Якщо провал → переглянути гіпотезу
- Якщо novelty CONFLICT → переформулювати оператор

---

## 4. Exploration 2 — Scaling

### 4.1 Тип
Scaling (прогресивне додавання датасетів)

### 4.2 Послідовність
1. **Tier 2**: spirals, blobs → зафіксувати де ламається
2. **Tier 3**: gaussian_quantiles, classification → більше класів
3. **Tier 4**: highdim, sequence_cls → інша зв'язність

### 4.3 Критерій зламу (на кожному Tier)
- speedup ≤ 1.0
- Q(f_C) < Q(f_S) − 0.05
- Дивергенція між seeds > 0.1 F1

### 4.4 Тригер переходу
- Якщо стабільний успіх на всіх Tiers → **Exploration 6 (Synthesis)**
- Якщо near miss → **Exploration 3 (Impossibility)**

---

## 5. Exploration 3 — Impossibility Proof

### 5.1 Тип
Impossibility Proof (математичне відсікання)

### 5.2 Гіпотеза
Існує структурний бар'єр, який робить оптимальну конверсію неможливою для мереж з певним типом зв'язності.

### 5.3 Метод
Побудувати математичний доказ або контрприклад.

### 5.4 Результат
Додається до **Hard Constraints** у plan.md.

### 5.5 Тригер переходу
- Після доведення бар'єру → **Exploration 4 (Reframing)**

---

## 6. Exploration 4 — Reframing

### 6.1 Тип
Reframing (зміна парадигми)

### 6.2 Правило
**ЗАБОРОНЕНО** використовувати терміни поточного підходу.

### 6.3 Метод
Переформулювати задачу. Запропонувати ≥3 альтернативних парадигми.
Кожна перевіряється через **Novelty Check** перед реалізацією.

### 6.4 Тригер переходу
- Після вибору нової парадигми → **Exploration 5 (Revision)**

---

## 7. Exploration 5 — Revision

### 7.1 Тип
Revision (переаналіз старих даних)

### 7.2 Метод
Результати Expl. 1–2 переглядаються під новою парадигмою.

### 7.3 Тригер переходу
- Якщо знайдено патерн → **Exploration 6 (Synthesis)**
- Якщо не знайдено → повернутись до Expl. 4 або зупинити гілку

---

## 8. Exploration 6 — Synthesis

### 8.1 Тип
Synthesis (фінальна конструкція)

### 8.2 Метод
Поєднати інсайти. Написати чистий код. Запустити на ВСІХ 8 датасетах × 2 seeds.

### 8.3 Фінальна перевірка на плагіат
Поопераційна перевірка кожного компонента фінального алгоритму проти всіх 18 операторів.

### 8.4 Критерій завершення
- Реальний speedup > 1.5× на ≥6 з 8 датасетів
- Q(f_C) ≥ Q(f_S) − 0.03
- Результати відтворювані по 2 seeds
- Novelty Check: OK по всіх категоріях A–H
