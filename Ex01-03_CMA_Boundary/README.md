# Ex01-03_CMA_Boundary — межа застосовності CMA-ES за розмірністю задачі

Обґрунтувальний (не новизна) експеримент розділу 2 дисертації: емпірично
встановлює межу, за якою еволюційна стратегія CMA-ES перестає бути
конкурентною порівняно з градієнтними методами. Саме ця межа мотивує перехід
від оптимізації неперервних ваг до **комбінаторних** задач (проріджування,
пошарова алокація), яким присвячено решту розділу 2 та розділи 3–4.

Відповідає § 2.2 дисертації («Обґрунтування конкурентоспроможності еволюційних
алгоритмів», підрозділи 2.2.1–2.2.2):

- **2.2.1** — CMA-ES проти градієнтних методів (AdamW, AdaBelief, обидва з 10
  рестартами) на багатомодальній функції Растрігіна, d = 10: W Кендала =
  **0,943** (Ex01).
- **2.2.2** — Adam проти чотирьох ЕА (CMA-ES, L-SHADE, CLPSO, RTS) та
  випадкового пошуку на прямій оптимізації ваг MLP (3 датасети зростаючої
  розмірності: moons, classification20, digits): зведений W Кендала =
  **0,700** (Ex03).

Висновок § 2.2 (дослівно): «ЕА ефективні на комбінаторних та багатомодальних
задачах низької розмірності (d ≤ 10¹, W Кендала = 0,943); ЕА
неефективні для прямої оптимізації неперервних ваг у просторах високої
розмірності (d ≥ 10², W Кендала = 0,700), причому розрив збільшується
з розмірністю».

Ex02 (не входить до цієї папки) — проміжна ланка того самого ланцюжка: той
самий протокол на чотирьох бенчмарках (Rastrigin, Ackley, Sphere, Rosenbrock)
і семи розмірностях (D = 2 … 40); показує, що перевага CMA-ES
специфічна для багатомодальних ландшафтів і зникає на унімодальних задачах
навіть при помірній розмірності. Його власні W Кендала (0,380 для
мультимодальної групи, 0,726 для унімодальної) в § 2.2 не цитуються, тому тут
не копіюється — джерело залишається `Ex02/` в основному репозиторії
експериментів.

## Перевірка відтворюваності

```bash
# Найшвидший спосіб — лише numpy/pandas/scipy, без torch і без common/:
python3 verify_kendall_w.py
```

Результат (перераховано напряму з `data/*.json`, формула W = χ² / (N(k-1))
— та сама, що й в оригінальних `ex0N_visualize.py`):

```
[Ex01] chi2=56.5800, p=0.000000, N=20, k=4
       W Кендала (перераховано) = 0.9430
       W Кендала (дисертація)   = 0.9430
       різниця = -0.0000  OK

[Ex03] chi2=52.5000, p=0.000000, N=15, k=6
       W Кендала (перераховано) = 0.7000
       W Кендала (дисертація)   = 0.7000
       різниця = +0.0000  OK
```

Обидва значення відтворюються **точно**, без округлення чи підгонки.

Скрипт додатково рахує W Кендала окремо по кожному з трьох датасетів Ex03
(реальні проміжні точки, той самий пул даних, що й у зведеному показнику):

```
classification20   dim(ваги)=  705  N=5  W=0.9261  p=0.0003
digits             dim(ваги)= 4810  N=5  W=0.9817  p=0.0002
moons              dim(ваги)=  129  N=5  W=0.8579  p=0.0007
```

Тут `dim(ваги)` — точна кількість параметрів MLP (ваги + зміщення), порахована
з `Ex03/code/ex03.py` (`build_model`/`MLPBinary`/`MLPMulti`). Це трохи більше
за наближені числа в тексті дисертації (moons ~97, classification20 ~673) —
там ідеться про приблизну оцінку «на око», тут — точний підрахунок за
формулою n_(in) h + h + h · n_(out) + n_(out); для digits обидва
джерела збігаються (4810).

### Повний канонічний конвеєр (ті самі скрипти, що згенерували рисунки 2.6–2.9)

Скрипти — точні копії з основного репозиторію експериментів, шляхи до
спільного `common/` (одна папка на корені `dissertation_repo_pub/`) підправлені
під глибшу вкладеність цієї папки (було `parent.parent`, стало на один рівень
глибше — обчислення статистики не змінено). Перевірено: обидва скрипти
запущено з цього місця і отримано **побайтово ідентичний** `ex01_stats.txt` /
`ex03_stats.txt` порівняно з основним репозиторієм.

```bash
# Потребує numpy, pandas, matplotlib, seaborn, scipy (+ спільний ../common/)
cd Ex01 && python3 ex01_visualize.py --data data/ex01_data_n20.json
# -> results/raw/ex01_stats.txt: "W = 0.9430"; results/figs/ex01_friedman_nemenyi.png

# Додатково потребує torch, scikit-learn (для панелі границь рішень)
cd Ex03 && python3 ex03_visualize.py --data data/ex03_data_n5.json
# -> results/figs/ex03_06_friedman_nemenyi.png: "W = 0.700, N = 15 повторів"
```

`ex01_run_experiment.py` / `ex03_run_experiment.py` та `code/` — код, яким
отримано самі дані (CMA-ES/AdamW/AdaBelief тренування на Rastrigin;
Adam/CMA-ES/L-SHADE/CLPSO/RTS/RS тренування MLP). Це багатогодинні прогони
(популяційні ЕА + 10 рестартів градієнтних методів), тому їх запуск не
потрібен для перевірки чисел — вони включені для прозорості методики, не для
повторного виконання. Не скопійовано `Ex03/code/or_ex03.py` — це чернетковий
архів раннього варіанту коду (містить рядок `!pip install`, синтаксис Jupyter,
не валідний Python-модуль) і не є частиною конвеєра, що генерує дані чи
рисунки; канонічний код — `Ex03/code/ex03.py`.

## Фігура: W Кендала vs розмірність задачі

```bash
python3 make_figs.py   # -> figs/kendall_w_boundary.png
```

Показує обидва цитовані в § 2.2 значення (Ex01 при d=10; зведений показник
Ex03 у діапазоні d = 129 … 4810) разом з трьома реальними проміжними
точками Ex03 по датасетах, у контексті меж застосовності ЕА (d ≤ 10¹ —
ефективні, d ≥ 10² — ні), як сформульовано у висновку § 2.2.
